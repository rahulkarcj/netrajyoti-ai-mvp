NetraJyoti MVP · Live project alignment · v6

Live MVP journey: Bengali-first safe guidance, care navigation, and family support

Current MVP user journey: PostgreSQL retrieves versioned demo criteria from structured screening facts; Java determines the safe route; PostgreSQL then retrieves route guidance. Ollama provides a short Bengali explanation only after the route is fixed and Java validates it. Location and patient details remain optional and consent-led.

Controlled RAG and Ollama explanation

Structured screening facts → PostgreSQL retrieves versioned demo criteria by input code → Java deterministic route → PostgreSQL retrieves route guidance → Ollama Bengali explanation → one final Java safety-and-audit gate. The explanation is available for urgent, routine and human-support routes. Ollama cannot diagnose, prescribe, change urgency or invent care-service details.

Live MVP safety and privacy rule

Fixed selected symptoms → Java-controlled safe route → versioned Bengali guidance. Optional voice/text does not decide urgency. District and town/city support demo service direction only. When enabled, Ollama provides a short Bengali explanation for urgent, routine and human-support routes only after Java selects the route. A single final Java safety-and-audit gate protects the response; a fixed Java safety fallback remains available. Patient identity details are client-side and only included in a message after explicit consent. The current PostgreSQL records are demo-simulated and not for clinical use.
